# 트러블슈팅 보고서 — EC2 외부 HTTP 접속 실패

EC2 배포 중 외부 HTTP 접속이 실패할 때의 원인 분석과 해결 절차를 정리한다.

| 단계 | 내용 |
| --- | --- |
| 증상 | EC2 내부 `curl -I http://localhost`는 `200 OK`인데, 외부 브라우저에서 `http://43.203.163.3/` 접속이 시간 초과로 실패한다. |
| 원인 가설 | Nginx 자체는 정상이고, EC2에 연결된 보안 그룹의 인바운드 규칙에서 TCP 80이 빠졌거나 소스가 외부 접속을 허용하지 않아 요청이 차단된다. |
| 검증 | (1) EC2에서 `sudo systemctl status nginx`와 `curl -I http://localhost`로 서비스 상태를 확인한다. (2) EC2의 퍼블릭 IPv4가 `43.203.163.3`인지 확인한다. (3) 연결 보안 그룹 `sg-026a47a0127dd4ae9`의 인바운드 규칙에서 `HTTP / TCP 80 / 0.0.0.0/0` 항목을 확인한다. (4) Public Subnet에 연결된 라우팅 테이블 `rtb-0efaf708b859572fe`에서 `0.0.0.0/0 → igw-08e9c5ffd8972dcf2` 경로가 활성인지 확인한다. |
| 조치 | TCP 80 인바운드 규칙이 누락됐다면 보안 그룹에 **HTTP / TCP 80 / 소스 `0.0.0.0/0`**을 추가한다. SSH 22는 개인 IP `/32` 제한을 유지한다. |
| 결과 확인 | 변경 후 외부 브라우저에서 같은 URL을 다시 열어 `Welcome to nginx!` 표시를 확인한다. 외부 클라이언트에서 HTTP 요청이 `200 OK`를 반환하는지도 확인한다. |
| 재발 방지 | EC2 배포 체크리스트에 **퍼블릭 IP, 서브넷의 IGW 경로, 보안 그룹 80 허용, Nginx 실행**을 넣고, 내부 응답과 외부 응답을 각각 확인한다. |
